## 阶段 1: 修复资源泄漏 ✅

### 问题
- 6 个未关闭的 SQLite 数据库连接警告
- 测试间资源未正确清理

### 解决方案
1. **优化数据库引擎初始化** (`src/examforge/repositories/engine.py`)
   - 添加 `pool_pre_ping=True` 检测连接有效性
   - 添加 `check_same_thread=False` 支持 SQLite 多线程
   - 设置 `expire_on_commit=False` 减少不必要的刷新

2. **增强资源清理** (`reset_db_engine_for_tests()`)
   - 确保 `_session.close()` 
   - 添加 `_engine.dispose()` 释放连接池
   - 设置全局变量为 `None`

### 结果
✅ 所有资源警告消除
✅ 测试运行更稳定

## 阶段 3: 提升代码质量 ✅

### 问题
- `http_llm.py` 有 383 行,重试逻辑复杂且重复
- 错误处理分散,难以维护

### 解决方案

1. **创建重试策略模块** (`src/examforge/llm/retry_policy.py`)

     - `_compute_max_tokens()` - Token 计算
     - `_raise_connection_error()` - 错误转换
   - 消除重复的异常处理代码
   - 改进错误上下文传递

### 代码质量改进
- **方法职责更清晰**: 每个方法只做一件事
- **可测试性提升**: 更容易单独测试每个部分
- **可维护性提升**: 重试逻辑集中管理

## 阶段 4: 性能优化 ✅

### 问题
- 数据库查询逐个执行,N+1 查询问题
- 缺少批量操作支持
- 无分页支持

### 解决方案

1. **仓库批量操作** (`src/examforge/repositories/method_repo.py`)
   - `get_many()` - 批量获取方法 (单次 SQL 查询)
   - `add_many()` - 批量添加方法 (单次事务提交)
   - `update_many()` - 批量更新方法 (单次事务提交)

2. **仓库批量操作** (`src/examforge/repositories/problem_repo.py`)
   - `get_many()` - 批量获取题目
   - `list_by_area()` - 添加 `offset` 参数支持分页

3. **批量操作测试** (`tests/repositories/test_batch_operations.py`)
   - 新增 6 个测试验证批量操作
   - 测试分页功能
   - 测试边界情况(空列表等)

### 性能改进
- **数据库查询**: 批量查询 N 个对象从 N 次查询减少到 1 次
- **事务提交**: 批量更新 N 个对象从 N 次提交减少到 1 次
- **预期提升**: 批量操作场景下性能提升 10-100 倍

### 结果
✅ 添加批量操作 API
✅ 6 个新测试全部通过
✅ 向后兼容,不破坏现有代码
